委托不可变、event 与先存再退订：一次 C4 复习复盘

发表于2026-11-16|更新于2026-11-16|Unity
|字数总计:739|阅读时长:2分钟|阅读量:

这篇讲清一件事：委托是类型，Action / Func 怎么分，以及多播运算、event 的外部限制、lambda 退订这三条边界。

下面按主题给口径，不铺过程流水账。

委托本身是一种类型。Action 和 Func 是框架预定义好的委托类型，不是对 delegate 关键字的另一层封装。

二者的分界是有没有返回值：

  • Action ：无返回值
  • Func ：有返回值

参数个数两边都可以变 。不要说成「Action 规定返回、Func 规定参数个数」——返回值有无才是这条分界，参数个数不是只归一边管。

面试口径一句话：先问是不是一个类型，再问有没有返回值，最后才数参数。

委托不可变 ：+= / -= 之后，原来的对象还在。但运算结果 不总是新对象 。

  • 左边为 null 时，+= 只是把右边赋过去
  • -= 找不到要减的目标时，还是原引用
  • 减掉最后一个订阅者时，结果是 null
  • 其余情况才会得到新对象

有返回值的时候，拿最后一个 。中间有一个订阅者抛异常，后面的不会再跑 。

一句话：原对象在不在，和这一次运算得到的是不是新实例，是两件事。

event 在声明它的类外面，只能 += / -=。

  • 外部 不能
  • 外部 不能赋值 （不能写成 = 某个处理函数 把已有订阅冲掉）
  • 引发只属于声明它的类

委托变量本身没有这层限制；加上 event，就是把「谁能引发、谁只能增减订阅」切开。

lambda 每次写出来都是一个新的委托实例。不先存变量就 -=，减掉的不是当初订上去的那一个，退订是空操作 。

面试口径一句话：能退订的前提，是手里还拿着当初订上去的那份引用。

结论与未尽

上面把「委托是类型」、Action / Func 按有无返回值来分、多播里 += / -= 不总是新对象、event 的外部限制，以及 lambda 必须先存再退订，收成一套可复述的口径。

这一层不靠背「加了就是新对象」，而靠追问「左边是 null，或减到没人、减错对象时，结果分别是什么」时判断还能站住。
